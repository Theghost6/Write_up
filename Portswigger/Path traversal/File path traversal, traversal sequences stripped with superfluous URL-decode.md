# Phân tích và khai thác
Ở lab này load ảnh thông qua thông số `filename` và ta lại khai thác lỗ hổng file path traversal ở tham số này. Và ta thử travesal bằng cách `../../../etc/passwd` thì nó bị trả về method `400` -> có thể nó đã bị chặn hoặc xóa `../`![Pasted image 20250920171327.png](../../assets/portswigger/Pasted%20image%2020250920171327.png)
Ta sẽ thử encode URL ký tự `/` thành `%2f` , kếta quả cũng trả về `400` do đó có thể web đã endcode trước và server vẫn hiểu nó là `/` ![Pasted image 20250920171811.png](../../assets/portswigger/Pasted%20image%2020250920171811.png)
Có vẻ như server còn 1 bước URL decode nữa sau khi check `../` -> nếu ta double endcoding `../` -> `..%2f` -> `..%252f` thì khi submit request, server sẽ hiểu thành `..%2f`, và cái này trải qua 1 bước URL decode nữa sẽ thành `../` -> Ta bypass thành công và xem được nội dung của `/etc/passwd` với payload như trong ảnh dưới![Pasted image 20250920172158.png](../../assets/portswigger/Pasted%20image%2020250920172158.png)
